# PROJ-061 — OBS delivery, template refresh and connection state

16 October 2026. User reported an unexplained OBS collection name, failed screen sending, stale template previews, incorrect branding and a Connect button shown while OBS was connected. Changes are local and uncommitted. This supersedes the no-data/brand descriptions in the previous charcoal handoff.

## Verified causes and fixes

1. **Screen delivery blocker:** read-only diagnosis of the running local OBS found version 32.2.1, the existing scene collection named by the user, zero Air scenes/browser sources, inactive streaming/recording, and GetReplayBufferStatus failing with OBS code 604. Air inspected that optional replay capability alongside required version/collection/scenes/transitions and treated any failure as setup failure. Replay status is now optional: unavailable replay remains unavailable; required inspection still blocks setup when incomplete. The corrected readiness check passed against the real OBS without changing its scenes or outputs. This is not proof of an actual user-template send after restart.
2. **Collection wording:** the displayed collection name was returned by OBS, not injected demo data. The UI now labels OBS version and Scene collection separately. Sending adds Air-managed scenes to the selected collection; no automatic collection rename/switch was introduced.
3. **Connection state:** Connections previously always rendered the Connect form despite a connected status sentence. It now reads actual OBS status, follows connect/disconnect events, hides credential fields while connected and shows Disconnect OBS. A confirmed disconnect restores Connect. Read failures are shown as unavailable, not disconnected. Removed unverified on-air-output/offline-continuation claims and shortened capture copy.
4. **Templates added inside Air:** unsaved editor state used to disappear when moving to HUD controls. The workspace now retains drafts and selection by source/show/match/node during navigation, preserves conflicting edits and keeps explicit Save/Send. Adding a template changes the local draft, not OBS. A delivery-state label and visible Send action distinguish these states. A Stop Air session action with confirmation is available in production controls when active; it uses the existing runner stop and preserves the OBS output/stream. Save draft before quitting; this navigation cache is not a replacement for durable saved drafts.
5. **Apparently frozen preview:** No game data previously hid every chosen screen. Static Opening/Break/Introduction/talent/branding designs now render with configured teams/content and without sample results. Gameplay statistics remain hidden until an explicit sample or received-data mode. Unsupported empty gameplay previews explain this. HUD settings retain in-frame updates rather than reloading.
6. **Feed label:** the top-right status now reports Game data: waiting or the age of the last game data. It opens Live match; its tooltip explains the measured value. It does not describe OBS connectivity or template updates.
7. **Branding:** the actual bundled Esportra symbol and wordmark replace the improvised SVG/text logo and hero mark. Local assets work offline and invert in light mode. Primary controls/identity follow the platform primary token from D:/frag-and-book-main/src/index.css (hsl(259 94% 60%); a lighter dark-mode accent), while charcoal surfaces remain.
